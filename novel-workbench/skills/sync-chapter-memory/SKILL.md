作者已经保存正文修改，并要求核对记忆。核对由宿主的核对程序完成：范围（改过几章就逐章核对几章，章与章互不牵连）、清理旧记忆、逐章重记、篇章与卷摘要、体检都在程序里，以已保存的正文为准，不改正文、完成进度、作者决定与风格样本。你负责判断哪些是真矛盾、登记，再用作者的话汇报。

作者看到的说明只讲章节、剧情、决定和进度，不堆工具名、版本号或内部字段。作者已授权这次核对，范围由宿主定，不再询问。作者停止、取消或预算耗尽时立即停止。

## 1. 核对

用一句话说明这次要核对作者改过的章，随即调 `project_memory_reconcile`（不传参数）。

- 结果 `status: "done"`：`chapters` 是这次核对了记忆的章；`mode: "none"` 表示记忆本来就与正文一致，只做了体检。有 `cleared` 时，那几章的正文已不在，模型记的记忆已清掉、作者自己写的修正留着，汇报时告诉作者。
- 结果 `status: "stopped"`：如实说明卡在哪一步、原因是什么，不自己绕过。
  - `blocker.authorDecision` 为 true：作者之前的决定挡住了核对。说清是哪条决定（`blocker.records` 里的人物与内容），告诉作者作品概览的「待处理」里已经登记了这一条，改或撤回那条决定后点「核对记忆」再核对。不要再调一次核对，结果不会变。
  - `resumable` 为 true：已核对的部分保留，下次核对会接着做。

## 2. 判断矛盾并登记

结果里的线索只是线索，要对照正文判断真伪：

- `clues.conflictReport`：体检筛出的跨章矛盾线索；
- `clues.keeperReports`：记进记忆时发现的前后说法对不上（本章原句与前文说法）；
- `clues.edits`：核对了的章里作者改了哪些句子（改前 → 改后；`omitted` 是没列出的处数，要看全就读正文）。

需要证据时 Read 当前正文与设定。对照本书指令、作者已确认的决定（用项目记忆查询取）和当前正文逐条判断。

体检只比同一章里的说法，后文也不跟着重记，查不出后文仍用旧说法。`clues.edits` 里改掉的说法（编号、名字、数目、物件等），或记进记忆时发现本章某个说法变了，就按旧说法 Grep 后文正文与大纲、用 `project_memory_query` 查记忆，看还有没有在用；查到就读那一章正文核实。仍写着旧说法的，登记在这次核对的章下面，severity 为 hint，逐字摘出两处原话；回复里问作者「第 N 章仍写着 X，要一起改吗」，不发问答卡，不替作者改后文或大纲。

每个核对过的章调一次 `project_diagnostics_report({chapter, items})`：仍成立的正文矛盾每条给逐字证据；没有矛盾也传空数组。只做了体检时，为作者要求核对的章登记一次。登记只进作者的「待处理」，不改正文或记忆；回执里 suppressed 的条目是作者已记为决定的，回复里不再当新问题提。

## 3. 汇报

按作者语言报告核对的章范围、更新了什么、仍需作者处理的正文矛盾。矛盾如实列出，说明是作者这次修改的跨章影响，由作者决定是否处理，不为消除冲突擅改正文、后续章记忆或作者决定。完成核对不代表正文矛盾已经解决：作者决定与正文冲突、未纳入记忆的抽取都要在报告中说明，不能因为体检为零而省略。

新增、更新、失效的记录数量只是合并结果，不代表正文冲突或旧记忆有错。不能仅凭这些计数宣称“自动纠正了矛盾”或“旧记忆与正文不一致”；需要指出实际冲突的来源与内容才作此判断。物件身份或时间衔接不明确时，说明不确定之处，不能自行认定两处提及的是同一物件。报告保留待处理事项时，不再笼统宣称“无需其他处理”。

中断或停下时说明已完成到哪、还缺什么；下次核对会接着做，不重新清空已核对的部分。
