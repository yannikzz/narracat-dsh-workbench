# 本书本体构建

本书本体回答的是「这本书要记什么」：有哪些**实体类型**（人物、地点、势力……），每类实体有哪些**状态维度**（境界、生死……），实体之间有哪些**关系种类**（所在、师徒、婚配……）。记忆管理员每章按它记，状态卡按它显示，矛盾检查按它比对。合身的本体让记忆清楚好查；不合身的本体会让记录堆进「待归类」，或者把不同的东西塞进同一个筐。

你只写**名字**，编号由系统生成。改动作者确认之前不生效。

## 一、先定位：四个维度

读立项卡（或简介、前几章），给这本书定四样东西，再只读对应的参考文件：

| 维度 | 定几个 | 参考 |
|---|---|---|
| 题材：世界长什么样 | 1 个主题材，必要时加 1 个副题材 | `${CLAUDE_PLUGIN_ROOT}/skills/novel-book-ontology/references/genres/<题材>.md` |
| 元素：可叠加的机制 | 0 到多个 | `${CLAUDE_PLUGIN_ROOT}/skills/novel-book-ontology/references/elements/<元素>.md` |
| 感情线：关系配置 | 1 个 | `${CLAUDE_PLUGIN_ROOT}/skills/novel-book-ontology/references/romance.md` |
| 时代：常识约束 | 1 个 | `${CLAUDE_PLUGIN_ROOT}/skills/novel-book-ontology/references/era.md` |

题材文件名：仙侠修仙、东方玄幻、西方奇幻、武侠、都市生活、都市异能高武、历史架空、军事谍战、星际未来、末世废土、悬疑推理刑侦、灵异民俗、无限流、游戏竞技体育、宫廷权谋、宅斗家族、豪门职场、青春校园、种田经营、年代、娱乐圈。
元素文件名：系统面板、重生、穿越、穿书、快穿、随身金手指、马甲多重身份、规则怪谈、副本任务制、直播、世界剧变、诸天万界、ABO兽世。

拿不准归哪个题材，按「读者点进来期待看到什么」和正文里实际运转的机制定主题材，不按出现过的零星元素，也不按书名字面（「规则系法宝」不等于规则怪谈）。外壳和内核不同的书（末世外壳、警匪崛起内核），把内核题材加为副题材，两份参考都读；**副题材只借和本书主线相交的一两项**，参考里写了加入条件的（如刑侦的「案件」只在单元案、系列案的书里加）先满足条件，不整套照搬。参考文件是起点不是清单：照搬整份不如挑这本书真用得上的。

## 二、从起步模板出发

每本书都从官方起步模板开始。模板现有：

- 实体类型：人物（固定）、地点、势力（又称门派、组织）、物件、概念、其他
- 人物维度：身份（单值，身份标记）、生死状况（单值，生死标记，终态「死亡」及同义词：已死、身亡、战死、陨落、牺牲、遇害……）、秘密（多值，秘密标记）、目标、伤势、能力、誓约、债务（多值）、声望（单值）
- 关系：关系（通用，双向）；所在（人物 → 地点，单值，所在标记）、下落（物件 → 人物或地点，单值）、所属（人物 → 势力，多值）。后三种程序要拿来算（同时在两处、地点里现在有谁、东西在谁手里），只改名字和说明，不改方向与单值多值
- 已停用：持有物（东西在谁手里改记物件的下落）。参考表里标「关系」的所在改的是关系的说明，不另开维度。较早的书本体里所在还是维度、没有下落和所属：可以提议加这三种关系（写清方向、单多值，所在带所在标记）并让所在维度由所在关系接替，作者确认后老记录自动跟着搬

在模板上做四类改动：

1. **改**：名字换成这本书的叫法（「声望」在宅斗里叫「宠眷」）；自由维度改成梯子（「能力」在修仙里拆出「境界」梯子）；改终态。旧名会自动留作别名，已记下的内容不受影响。
2. **加**：这本书特有、后文要反复查的状态（「血门进度」「位分」「异能等级」）。
3. **停用**：这本书明显用不上的（纯恋爱都市文的「誓约」）。停用只是不再列给记忆管理员，已记下的保留。拿不准就不停用。
4. **关系种类**：起草时不按题材预设别的种类；书里反复出现、需要按种类单独查的（师徒、主仆、婚约），等记录进了待归类再提议（第六节）。「关系」通用兜底保留。

## 三、维度怎么定

**只加「持续成立、直到被改变」的状态**，后文写作或查证要用到它。不加：
- 一次性的动作和经过（「打了一架」「救了某人」）——那是事件，系统另有记录；
- 正文里看不出、只在设定里存在的东西；
- 评价和感受（「很勇敢」）。

每个维度写清：
- **挂哪类实体**：多数挂人物；势力的「实力排名」、地点的「是否封锁」挂对应类型。
- **单值还是多值**：同一时刻只能有一个值的是单值（境界、位分），能并存的是多值（技能、秘密）。单值维度出现两个同时有效的值会被矛盾检查报出来，所以别把能并存的东西设成单值。
- **取值**：自由填写、有序梯子、数值。**梯子**用于有明确档位、按递进次序变化的（练气→筑基→金丹；答应→贵人→嫔→妃），档位按低到高排，2–10 档常见；档位名用书里的原词。梯子维度的值只能是档位之一（完全相等比对）：同一档里的细分（初期、后期、大圆满）要么另开一个单值梯子，要么不记，不写进值里。拿不准档位全不全就用自由填写——梯子外的值会被提示核对，太早定死会添噪声。**数值**用于书里真用数字的（积分、寿元、好感度）。
- **终态**：只有真正不可逆、此后人物不该再有新状态的值才设终态（多数书的「死亡」）。**看这本书的证据，不按题材一刀切**：素材里死者会再行动（复活、化鬼、回档、夺舍、死后照常出场）就不设，否则每次正常出场都会被报成「死而复生」；死亡是真实代价、没有复活机制的，保留死亡终态。先按题材参考给的默认（仙侠只设「形神俱灭」、末世尸变不算终态），再看本书证据修正：本书已有魂穿、夺舍、残魂、死后照常出场，就算「死者会再行动」。证据和参考都拿不准时才保留「死亡」终态：误报看得见、作者能改，漏报看不见。
  - **终态按「包含」比对**：值里含任何一个终态词就算到了终态。所以保留死亡终态时不要写 `terminal_values`（模板已带同义词，重写一遍会丢掉它们，只补本书特有的说法如「殉职」）；改成别的终态时把本书的同义说法一起列上（形神俱灭、魂飞魄散、神魂俱灭）；非终态的取值不能含终态词（写「下落不明」，不写「被传身亡」「疑似死亡」「肉身陨落」——后者要么去掉模板的「陨落」，要么换个说法）。
- **说明**：一句话，写给记忆管理员看：记什么、不记什么。用类别和书里的原词举例，不写具体人物、当前值或剧情（「苏见欠某人一笔账」会过期，还把状态值写进了本体）。保留的模板维度也看一眼说明里的举例是否适用这本书，不适用就改说明。
- **固定不变的属性不开维度**：法宝的规则、丹药的效果、副本的规则是设定，写进实体的说明或设定文件；只有会变的才是维度（「已被发现的效果」可以多值记）。

## 四、语义标记

只有四个，每类实体最多一处（维度或关系）带同一个标记。带标记的项系统有专门规则：

| 标记 | 含义 | 系统规则 |
|---|---|---|
| 所在 | 人在哪 | 同一时刻两地即报矛盾 |
| 身份 | 公开身份/职位 | 同一时刻两个即报矛盾 |
| 生死 | 生死状况 | 终态之后再出现会被报出 |
| 秘密 | 别人不该知道的事 | 唠个嗑时，角色本人不知道的不说 |

改名不影响标记。把模板的「秘密」换成本书叫法时保留标记；本书另有更贴切的秘密维度（「隐藏身份」「真实来历」）时，把标记挪过去，原维度去掉标记或停用。没有标记的维度功能完整，只是没有这几条专门规则。

## 五、数量与纪律

- 人物维度连模板一般 **8–16 个**。题材与元素参考列的是候选，叠在一起常常超过这个数，按立项卡挑这本书真会反复写到的，其余不加。多了记忆管理员难选、状态卡变长；宁缺勿滥，后面还能提议补。
- 同一件事只记一处：
  - 两个维度不记同一件事（「境界」和「修为」只留一个，另一个作别名）；生死维度只记生死（存活、下落不明、死亡、残魂这类），伤病归伤势。
  - 维度和关系分工：指向一个具体实体（在世的人、门派、地点、物件）的记关系（「仇人」「所属」）；维度只记没有特定对象、对象是已故者的（欠亡父的账）。关系两端可以是任何类型，加种类时写清起点、终点类型与有没有方向。
  - 谁知道一件秘密只记一处：书里加了「知情」维度，秘密只记本人藏的事、谁知道记在知道的人的知情里；没加知情，就把谁知道写在秘密那一条的值里。
  - 外挂、系统产出的物件后文要用就记它的下落，外挂维度只记外挂本身。
- 名字用这本书的原词，短（2–6 字），不带书名号与括号。梯子档位也用原词（书里叫「结丹」就不写「金丹」），不把参考里的长梯子整段照抄，书里出现到哪排到哪。
- 新维度、新关系种类必须是**类别**，而且素材里反复出现：不为一句话里的说法或某一对人的专事单开（「某人欠某人一句话」是关系值，不是关系种类）。
- 说明里提到别的维度时，用这本书改名后的名字（伤势改叫病症，就写「病症另记」）。
- 每条改动附一句理由，写给作者看：依据立项卡哪条、或正文哪类反复出现的状态。

## 六、整理待归类

已经在写的书，记录里会有本体还没有的名字（待归类）。用 `novel_ontology_unclassified` 看按名字分组的条数、样例与章节范围，每组判断：

- **是已有维度的另一个叫法** → `add_alias` 并进去（「修为」并进「境界」）；
- **是这本书真需要的新状态**（反复出现、持续成立、后文要查）→ `add_dimension`，名字用最常见的那个叫法，其余叫法作别名；
- **是关系种类**（两端各是一个实体，如师徒、婚约）→ 优先 `add_alias` 并进已有种类；真需要单独查才 `add_relation`，写清起止类型与方向，默认多值；
- **是一次性的动作、经过或评价** → 不处理，留在待归类（它们本该记成事件）；
- **只有一两条、拿不准** → 不处理，等多了再说。

一次提一批，每条附依据（涉及哪些记录名、多少条）。
