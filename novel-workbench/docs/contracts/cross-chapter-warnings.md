# 契约：写手包里的跨章预警（已撤）

> **现状：** 写作上下文包（`novel_build_writing_context_pack`）不再做跨章排期扫描，`warnings` 数组只放数据缺口提示（世界规则未填、前章 brief 缺失、未解析出出场角色等）。原先的三条扫描已撤，理由见 App 仓库根 `docs/adr/0088-official-novel-scheme-redesign-principles.md`（2026-10-19 附记）：**收件人错**——它们是写给大纲的排期建议，却进了写手包，写手拿到也改不了排期，只会在本章硬塞一段。

## 已撤的三条

| 原规则 | 原输出 | 为什么撤 |
|---|---|---|
| 故事线连续未聚焦（活跃线连续 ≥5 章不在本章聚焦里） | 「故事线 X 已连续 N 章未聚焦，可在本章用一次间接提及……」 | 哪条线该在哪章出场是大纲的事；写手照做就是往本章里加戏 |
| §4.2 伏笔无兑现（过了铺设期、有临期伏笔、近 3 章没有 develop / reveal） | 「已连续 N 章无伏笔兑现，建议本章安排一次小结算」 | 伏笔何时推进、何时兑现由章纲的伏笔动作决定；写手照做会越过章纲自造兑现 |
| §4.3 锚点泛泛（前 3 章锚点 core_experience 抽象词占比偏高） | 「前文锚点描述偏抽象……本章 outline 可能也需要细化」 | 说的是章纲写得不够具体，收件人是写章纲的人，不是写手 |

## 仍在包里的

- 伏笔 due-list、故事线聚焦、贯穿线锚点照常作为**事实**进包：写手据此知道本章碰到哪些线与伏笔，但不附「该怎么排」的建议。
- 数据缺口提示照旧写进 `warnings`；预算截断、渲染降级等系统诊断走 `buildNotes`，只回主会话，不进包。

## 修改纪律

要把「排期建议」重新加回来时，先定收件人：给大纲的放在大纲提交或体检的回执里，给写手的只放写这一章用得上的事实（ADR-0088）。
