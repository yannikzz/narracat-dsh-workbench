# Narracat · 叙述猫

在 DSH 里**从零写一部长篇小说**：书架是一页可切换的封面海报。新建作品后，作品概览永远只给你**一个下一步**——开始立项、规划大纲、写第 N 章、完本并导出。Agent 负责取材料、推进流程、做检查；你只做创作决定。

这是从 Narracat 专业版蒸馏来的长篇小说工作台：书是文件，工作台只是它的视图；机械保证交给程序，判断交给模型。书的内容（书名、章节、正文、梗概、手稿）用宋体，工具的界面（目录、按钮、标签、面板）用宿主无衬线字体。

## 它做什么

- **从一句话开书**：点「新建作品」，填书名、题材、一句话想法、计划章数与每章字数；作品建在默认书库（可改位置），自动加入左侧工作区。建完对话框立即关闭，书架自动刷新并打开新书；一句话想法会记进 `AGENTS.md`，Agent 每轮都能读到。
- **任何时刻只有一个下一步**：概览顶部是四阶段步进条（开书 / 搭骨架 / 写正文 / 完本）；下面一张下一步卡，按钮文字就是动作。立项、大纲、补章纲会打开写作会话；写章在后台跑，不切走页面。
- **完本与导出**：写满计划章数后下一步变成「完本并导出」；也可以随时从概览导出 Word（.docx）/ HTML（可打印成 PDF）/ Markdown / TXT。导出前先看全书体检（缺章、短章、记忆、审校、伏笔）。
- **看得见的记忆**：`tracking/` 下有进度、章节摘要、伏笔表、人物状态四张自动表，以及一份作者可编辑的写作备忘。写完一章自动刷新；Agent 写下一章前先读记忆简报（最近 10 章摘要、人物当前状态、未收伏笔、作者备忘）。
- **认得出你已有的书**：扫描当前 DSH 工作区里带 `.narracat/config.yaml` 的目录（工作区根、一层子目录、或 `books/<书>` 这类两层书架都认），不需要导入、不复制、不改原文件。
- **书的结构一眼看完**：卷与段的划分、每章是否有正文/章纲、字数与目标、审校结论、伏笔登记、故事线、立项卡。章纲按结构化字段展示（价值转变、情感赌注、场景、出场人物…），原始 JSON 收进「打开原始文件」。
- **正文与设定直接编辑**：阅读视图用衬线排版；点「编辑」进入等宽编辑，`⌘S / Ctrl+S` 保存。保存前核对文件修改时间，别人改过就拒绝覆盖。
- **原始文件就是真相**：每一类内容都能「打开原始文件」，改 `.json` 时会先校验 JSON 合法性。
- **跟着 DSH 的主题**：颜色、字号、深浅色全部走宿主主题变量，不画自己的配色。

## 怎么用

1. 在 DSH 里打开一个工作区（Workspace），里面放你的 Narracat 作品目录，例如 `我的书/.narracat/config.yaml`。
2. 左侧栏点「Narracat · 叙述猫」图标。
3. 空书架点「**新建作品**」：填书名、题材、一句话想法（可不填）、计划章数、每章字数；建完对话框会自动关闭、书架自动刷新并打开新书，下一步是「开始立项」。
4. 点「开始立项」：写作会话打开，Agent 一次只问你一个最关键的问题；问完把立项卡交好。
5. 立项完成后下一步变成「规划全书大纲」；大纲好了会提示「补第 N 章大纲」或「写第 N 章」。写章在后台跑，完成后概览自动刷新。
6. 想改已发布的章：章节头部点「改写本章」——Agent 先开改写稿，改完再提交替换，不会碰正式正文。
7. 想交稿：概览点「导出成稿」，看体检、选格式、下载。导出写在 `exports/`，不改正文。
8. 在书架上点书卡或「继续」进入作品；图标条选书稿 / 构思 / 设定 / 资料；清单里选章节或条目；中间读/改；右侧看本章资料。
9. 右上角「新建写作会话」会用**Narracat · 叙述猫预设**直接开一个会话，Agent 接着就能读这本书。

## 追踪式记忆：进度 / 摘要 / 伏笔 / 人物

「资料 → 全书追踪」是四张表的可读视图：

- **进度**：已写/计划、字数、下一章、卷进度、下一步、体检、最近章节；
- **章节摘要**：按卷分组，每章摘要 + 事件；缺记忆/过期有标签；
- **伏笔表**：大纲登记的伏笔 + 各章记忆动作，自动标「待埋 / 埋 / 推进中 / 已收 / 逾期 / 缺动作 / 未登记」；
- **人物状态**：把每章记忆的「变为 / 获得 / 失去」折叠成当前状态，带发生章与最近变化；
- **写作备忘**：作者的话、待办和提醒，Agent 写下一章前会读到。

表由程序在提交、重记记忆、保存大纲/设定/作品信息后自动刷新。四张表是派生视图，工作台与 Agent 都不能手改；要改记忆请重记那一章。写作备忘是唯一可手改的追踪文件。

## 线性写作：工作台点「写本章」

写作是线性的，所以工作台按「一次性只跑一章」设计：

- **一个屏幕只留一个写章动作**：章节空态、章纲空态和写作等待态由内容区拥有主按钮；内容工具栏在这些状态下让出「写本章/改写本章」，应用栏只显示写作状态，目录底部不再重复「下一步」。
- **写作等待态**：点「写本章/改写本章」后，正文页变成正在写的现场——宋体「正在写第 N 章」、三点跳动、不确定进度线、已用时、`打开写作会话`、`查看本章纲`；需要作者回答时切琥珀色「去会话回答」，失败时原地「再试一次」。右侧小说面板复用同一套紧凑等待卡片。
- **一本书一个写作会话**：第一次点写章时自动建（预设「Narracat · 叙述猫」），之后一直复用它，前后章共享对话与决定；会话 id 按作品记在浏览器里。
- 工作台顶栏显示状态：`写作进行中 · 第 N 章` / `等待你回答 · 第 N 章` / `第 N 章已结束 · 点开查看`；点状态直接打开写作会话。等待态按书持久化，切换页面/刷新/重挂载后恢复章节、用时、目录「写作中」和顶栏状态。
- 完成检测：会话状态优先，另每 4 秒轻量查询一次作品；看到本章正文出现就自动把新稿件加载进当前正文页，不需要手动刷新。写完这一页会直接变成成稿。
- 其他写章动作在这一章跑完前禁用（线性写作不并发）；Agent 中途提问时状态变「等待你回答」，点开回答后它继续。

## 会话内视图「小说」：工作台 + 实时对话板块

在任意会话里，会话标题栏的视图页签会多出一个「**小说**」（与「对话 / 轨迹」并列）。切到它：

- 左侧仍是工作台（章节、人物、世界、大纲、立项、审校、记忆）；
- 右侧是**这条会话的实时对话板块**：直接读 DSH 的会话消息流（用户消息、Agent 回复、工具调用、流式输入中、正在执行的工具），随会话实时更新；
- **输入仍走 DSH 原生输入框**（视图下方那条），所以发送、停止、排队、审批、问答卡全部是原生的，不会出现第二套聊天引擎；
- 板块只做「看」：工具卡、审批卡、问答卡这类富交互仍在原生「对话」视图里呈现。

## 对话 + 右侧小说面板

DSH 的对话固定在**主栏**（插件不能把主会话的对话嵌进右侧面板），所以工作台采用与 Narracat 镜像的布局：

- **主栏**：和 Agent 的完整对话（消息、工具卡、输入框）。
- **右侧「小说」面板**：一块随阶段变化的工作台看板。
  - 立项：九张立项卡的进度、四张核心卡的内容、题材契约；缺哪张、下一步问什么一眼能看到。
  - 大纲：全书梗概、卷/故事线/谜底/伏笔数量、分卷范围，以及前三章章纲的就位情况。
  - 开写准备：全书大纲、第一章章纲、主要人物和世界规则各就位了没有；人物与世界条目可以直接点进设定。
  - 写正文：下一章、最近写、前情提要、缺正文/记忆过期/审校未过/未收伏笔等「要留意」事项，以及写作前线附近的章节列表。
  - 完本：全书章数、字数、审校与记忆概况、体检清单和导出入口。
  - 点开章节时：有正文读正文；只有章纲就展示场景、冲突、人物与收束；两样都没有则给出补章纲/直接开写的按钮。底部快捷问题会直接把提示词填进输入框并发给 Agent。
- 打开方式：会话右上角的「**小说**」按钮（仅在含作品的工作区出现）；或从工作台主面板点「新建写作会话」后自动打开。
- 面板里「完整工作台」会切回全页工作台（书/卷/章/人物/大纲/审校/记忆的完整视图）。
- 面板自带样式并按容器宽度自适应：窄栏单列；宽栏（≥620px）变成「主栏看板 + 右侧资料栏」，顶部封面、标题和四阶段条保持固定。
- 面板会自己更新：Agent 一轮结束立即刷新；平时可见时每 4 秒用轻量 `/stamp` 指纹比对一次（只 stat 文件，不读正文），没有该接口时退回 15 秒全量快照轮询；切回页面或窗口获得焦点也会补刷。标题下方会显示「Agent 正在处理」「已更新」或「同步于 HH:MM」。
- 从 AI 对话切回 Narracat 主页面时，会回到上次退出的书和页面（每本书分别记住分类、选中的章/人物、子视图和追踪页签），不会默认掉回书架。

## 边界（这个版本）

- **工作台可以裸文件编辑**；Agent 写章走提交程序（检查 → 记忆 → 发布），不是直接改正文。
- **记忆是文件版**：本章记忆写在 `.narracat/memory/ch-NNN.json`（摘要、事件、状态变化、伏笔动作）；人物状态、章节摘要、伏笔状态都在读取时按章折叠，`.narracat/memory.db` 仍只显示存在与大小。正文被手改后，记忆会标为过期，需要核对重记。
- **新建作品**：在书架新建；默认位置 `~/Documents/Narracat`，可以改。作品建在已有工作区里时复用该工作区，不重复注册。
- **受保护文件不可改**：`memory.db*`、正文提交日志（`.narracat/content/`）、资料原件、作者决定的提交链、版本历史与锁文件都由宿主程序维护，工作台拒绝写入。
- **一次只处理一本书的文本**：大文件读取上限 2 MiB、写入上限 4 MiB；超出会明确提示。
- **审核口径**：编辑器只做「语法/JSON 合法性 + 修改时间」检查，不替代 Narracat 的提交程序（检查 → 审校 → 记忆 → 保存）。直接改文件不会更新记忆库与审校记录；写章请走工作台的提交程序（检查 → 审校 → 记忆 → 保存），改完正文记得核对记忆。

## 安全
