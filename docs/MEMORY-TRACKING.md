# 追踪式记忆：把「通用 Agent 写小说」的经验接进插件

> 参考工作区：本机一个通用的 Agent 写作项目（只读参考；不随仓库分发）
> 目标项目：`01-novel-plugin` / `narracat-dsh-workbench`
> 日期：2026-11-19

## 0. 一句话

**长篇写作的记忆不是「把更多东西塞进上下文」，而是写下一章之前，稳定读到五样东西：进度、最近章节摘要、人物当前状态、未收伏笔、作者备忘。**

## 1. 参考项目怎么做

参考项目用一套非常朴素、但长期有效的追踪文件：

| 文件 | 作用 | 维护时机 |
| --- | --- | --- |
| `03_追踪/进度.md` | **新会话第一个读**：写到哪、下一章、卷进度、下一步、备忘、日志 | 每章写完 |
| `03_追踪/章节摘要.md` | 每章 3–5 行，写新章前读最近 10 章 | 每章写完 |
| `03_追踪/伏笔表.md` | 伏笔编号、埋设章、计划回收、状态（埋 / 半收 / 已收 / 备忘 / 延 / 待议） | 每章写完 |
| `03_追踪/人物状态.md` | 主要人物的实力、位置、关系、持有物品、认知、伤势 | 每章写完 |

写作循环写得很明确：**读进度 + 最近 10 章摘要 + 当前卷细纲 + 人物状态 → 写 → 跑机械检查 → 更新四个追踪文件 → 每 5 章 commit → 每案/每卷盲读**。

这套东西的价值不在 markdown，而在三个约束：

1. **读的顺序固定**：先进度，再最近摘要，再人物状态，最后伏笔；不靠模型临时回忆。
2. **写的时机固定**：每章写完就更新，不攒到最后；记忆和正文同步推进。
3. **状态可核对**：伏笔有编号和回收计划，人物有当前值，进度有下一章；作者/审校能直接指出哪里不对。

## 2. 为什么插件不能照搬

- Narracat 桌面端的记忆在 SQLite（`memory.db`）里，插件不解析它；再建一套 SQLite 只会重复。
- 纯 markdown 作为唯一真相很脆弱：模型改错一行、漏一个伏笔号、把「已收」写成「埋」，没有机械校验；项目大了以后，四个文件会互相矛盾。
- 让 Agent 每章手工改四份大 markdown，既费 token，也容易把作者的备注覆盖掉。
- 上下文窗口有限；500 章的全量摘要不能每轮都塞进去。

所以，插件采用**「结构化源 + 可见派生表」**：

- **源**：每章记忆 `.narracat/memory/ch-NNN.json`（摘要、事件、状态变化、伏笔动作、正文版本）；
- **源**：全书大纲的 `foreshadowing_registry`、人物身份 JSON、`bible/`、`AGENTS.md`、写作备忘；
- **派生**：`tracking/` 下四张人可读的表，由程序生成，作者和 Agent 读同一份；
- **读取**：写作前用 `novel_memory_brief` / 上下文包取「最近 10 章 + 当前状态 + 未收伏笔 + 备忘」；
- **写入**：提交/重记/大纲/设定保存后自动刷新四张表；作者的决定用 `novel_tracking_note` 落到备忘。

这保留了通用 Agent 工作流的「读什么、何时读、何时更新」，同时把「手工维护」换成「程序折叠 + 机械校验」。

## 3. 五样东西

### 3.1 进度

来自正文与记忆，不是单独写一份状态：

- 已写章 / 计划章、总字数、下一章；
- 卷进度（按大纲卷范围 + 正文实际章）；
- 当前阶段与下一步（复用 `computeJourney`）；
- 记忆覆盖：已记、缺记忆、过期；
- 体检项：缺章、短章、审校未过、伏笔逾期。

落在 `tracking/进度.md`，工作台「资料 → 全书追踪 → 进度」同源展示。

### 3.2 章节摘要

每章记忆里的 `summary`（3–5 行）与 `events`（按顺序的事件），按卷分组渲染成 `tracking/章节摘要.md`。

写下一章时，`novel_memory_brief` 默认带最近 **10 章** 的摘要；上下文包也带同样 10 章，并额外带每章开头/结尾各一段。参考项目的经验是：**最近 10 章足够接住语气和悬念，再多只是成本**。

### 3.3 伏笔表

把「全书大纲登记的伏笔」与「各章记忆里的伏笔动作」合并：

| 状态 | 判据 | 含义 |
| --- | --- | --- |
| 待埋 | 还没到埋设章 | 计划中 |
| 埋 | 最近动作是 plant | 已埋，等推进 |
| 推进中 | 最近动作是 develop | 正在用 |
| 已收 | 最近动作是 reveal | 回收完成 |
| 逾期 | 计划回收章已过，仍未 reveal | 需要处理 |
| 缺动作 | 已到埋设章，但记忆里没有动作 | 正文可能埋了，记忆漏了 |
| 未登记 | 记忆里有动作，大纲没登记 | 需要补大纲或删动作 |

`tracking/伏笔表.md` 和追踪视图都显示这七种状态；写作简报只带「未收 + 到期」。

### 3.4 人物状态

把人物身份（年龄、性别、别名、速写、初始状态）与每章记忆的 `state_changes` 做**读时折叠**：

- 当前值：某维度最后一次 `set/add/remove` 的结果，标注发生章；
- 最近变化：最近 5 条，带操作和值；
- 没有状态变化的人物也列出，显示「还没有记过状态变化」，避免以为漏了人；
- 已建档但从未出场的人物、只在记忆里出现的人物都保留。

维度的显示名优先用本书的 `state-vocabulary`，没有就用常见维度词典（位置/持有物/关系/认知/身体/能力…）。

### 3.5 作者备忘

`tracking/写作备忘.md` 是**唯一一份不自动生成**的追踪文件：

- 作者的决定、要盯的细节、待办、临时提醒；
- Agent 用 `novel_tracking_note` 追加（带日期和可选章号），不直接改文件；
- 写下一章前，`novel_memory_brief` 和上下文包都会把备忘原文带上。

这对应参考项目 `进度.md` 里的「备忘 / 写作注意 / 日志」，但单独成文件，避免每次刷新进度时覆盖作者的话。

## 4. 读写链路

```
写章前
  novel_memory_brief(chapter)
    进度 + 最近 10 章摘要 + 人物当前状态 + 未收/到期伏笔 + 作者备忘
  └─ novel_build_writing_context_pack(chapter)
       再加上章纲、出场人物卡、前 3 章开头/结尾、相关设定、到期伏笔
写章
  project_chapter_submit（检查 → 写本章记忆 → 发布）
     └─ 自动 refreshTracking
          tracking/进度.md
          tracking/章节摘要.md
          tracking/伏笔表.md
          tracking/人物状态.md
          确保 tracking/写作备忘.md 存在（不覆盖）
作者改主意 / 记提醒
  novel_tracking_note(note, chapter?)
     └─ 追加到写作备忘
正文手改后
  project_memory_reconcile → novel_memory_record（逐章）
     └─ 自动 refreshTracking
大纲 / 设定 / 作品信息保存后
  └─ 自动 refreshTracking（伏笔、人物、卷进度）
```

## 5. 机械保证

- **一张表只有一个生成者**：四张表由程序生成，正文/记忆/大纲/身份是源；工作台和 Agent 都不手改生成表（写入被拒）。
- **过期不静默**：章节记忆带正文版本；正文改过，摘要与人物状态可能过期；追踪表会标「记忆过期」，写作简报也会提示。
- **缺记忆可见**：已写章没有记忆时，摘要表写「缺记忆」，进度表计入「记忆缺失」，不会假装有摘要。
- **伏笔有编号**：未登记动作、逾期、缺动作都会单独标出，不再靠模型记不记得。
- **作者备忘不被覆盖**：刷新只追加/保留，不重建。

## 6. 工作台入口

「资料」分类下新增 **全书追踪**：

- 进度：已写/计划、字数、下一章、卷进度、下一步按钮、体检、最近章节；
- 章节摘要：按卷分组，每条摘要 + 事件，缺失/过期有标签；
- 伏笔表：七种状态、埋设/计划回收、最近动作与依据章；
- 人物状态：当前状态、最近变化、人物档案入口；
- 写作备忘：直接编辑 `tracking/写作备忘.md`；
- 顶部「刷新」：重建四张表并重新读取快照。

## 7. 与参考项目的取舍

| 参考项目 | 本项目 |
| --- | --- |
| 四个 markdown 是唯一真相 | 章节记忆 JSON + 大纲 + 身份是源；四个 markdown 是派生视图 |
| 每章手工改四个文件 | 提交/重记/大纲/设定后自动刷新；Agent 用工具，不手改 |
| `进度.md` 里混设备忘与日志 | 进度自动生成；作者备忘单独 `写作备忘.md`，不被覆盖 |
| 每章重读四个大文件 | 写作简报只带最近 10 章、当前状态、未收伏笔、备忘；上下文包再加章纲/设定 |
| 人物状态是叙述性长文 | 结构化 `state_changes` 折叠 + 可选速写；可被程序核对 |
| 伏笔表手工维护 196 行 | 大纲登记 + 记忆动作折叠；自动标逾期/缺动作/未登记 |
| 每卷手工 build | 导出仍走 `export`；追踪表不参与成书 |

没有照搬：SQLite、Electron、四栏、每卷人工 build、盲读流程（盲读仍可作为 Agent 的按需动作，不写进每章强制流程）。

## 9. 下一步

1. **语义一致性检查**：人物状态跨章矛盾、伏笔逾期、时间线冲突；只报告，不改稿。
2. **人物状态词表按书定制**：让「实力/伤势/香火」这类维度进入本书 `state-vocabulary`。
3. **卷摘要**：在章节摘要之上折叠每卷摘要，给跨卷写作用。
4. **追踪随导出**：导出成稿时附带一份 `追踪.md`（进度 + 未收伏笔 + 人物状态），方便交稿说明。
