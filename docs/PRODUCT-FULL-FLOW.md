# 小说全流程：产品方案与实现记录

> 目标项目：`01-novel-plugin`（DSH bundle `narracat-dsh-workbench`）
> 参考项目：`narracat-pro`（桌面端，只读参考，不照搬实现）
> 日期：2026-11-19
> 状态：**P0 已落地**，P1 / P2 为路线图

## 0. 一句话

**把「写一部长篇小说」变成「任何时刻只需要做下一件事」。**

作者负责创作决定，Agent 负责取材料、推进流程、做机械检查；工作台只呈现书、进度、下一步和体检，不把工程结构丢给作者。

---

## 1. 用户是谁，真正卡在哪

目标用户不是「不会写字的人」，而是**没有小说工程经验、但有表达欲的普通作者**。他们会写句子，但不知道：

1. **开书卡住**：有一个画面或一句话，但不知道先定什么、人物怎么立、大纲怎么搭。
2. **中间迷路**：每次打开作品，不知道今天该写哪、该改哪、该补哪；工具里全是章节、设定、大纲、记忆、审校，术语先劝退一半。
3. **写不动**：每次写章都要自己组织前情、人物状态、伏笔；Agent 要作者先学会「怎么提问」。
4. **不敢改**：改一章怕前后矛盾；审校、改写、记忆是三个分离的动作，不知道先后。
5. **完不成**：没有「写完了吗、还差什么、怎么交稿」的终点；写到一半就散了。

桌面端 `narracat-pro` 把这些拆成了完整的创作链：立项 → 设定 → 大纲 → 章节 → 完结，并用「下一步」指针、空态、审校/改写/记忆、待处理页和导出把链子接起来。它验证了一个关键事实：**作者需要的是引导，不是更多面板**。

本方案借鉴它的产品判断，但按 DSH 的形态重新设计：

| 桌面端做法 | 本项目的选择 | 原因 |
| --- | --- | --- |
| 立项 / 设定 / 大纲 / 连载 / 完结五阶段 | **四阶段**：开书 → 搭骨架 → 写正文 → 完本 | 新手能一次记住；设定与人物降为写作中的支持项，不单独设卡 |
| 「下一步」按 project.status 与逐章状态实时算 | 同一个纯函数 `computeJourney()`，UI 与 Agent 共用 | 避免界面和 Agent 给出两个不同的下一步 |
| 设置与人物是独立阶段，可跳过 | 立项后直接进大纲；人物作为体检提示 | 少一步，少一次「我是不是漏了什么」的焦虑 |
| 新建作品 → 概览，不自动调模型 | 同左；建书是作者动作，建完自动打开概览 | 位置与成本由作者掌握 |
| 导出 MD / TXT / DOCX，整本导出 | **Word / HTML（可打印 PDF）/ Markdown / TXT** 单文件导出 | 一个文件就能交稿、备份、发给朋友 |
| Electron 原生目录、SQLite 记忆、多进程 | 文件即真相；记忆逐章记录、读时折叠；DSH 会话与工具 | 不重建宿主；书可以在任何编辑器里打开 |
| 岗位派发 + 四栏工作台 | 一个写作会话 + 工作台三栏；Agent 用 Skill 工作 | DSH 的会话就是协作现场，不再造第二套壳 |

## 2. 产品原则

1. **只有一个下一步。** 概览最显眼的位置永远是一张「下一步」卡；按钮文字就是动作本身（开始立项 / 规划全书大纲 / 写第 4 章 / 完本并导出）。不把导航做成执行，也不并列三个主按钮：顶栏只显示状态，目录底部不复制下一步，空态和写作等待态各自接管自己的主按钮。
2. **每步都可跳过，且不记录「跳过」。** 不想先建人物就直接规划大纲；条件不再成立时提示自然消失。跳过不是欠账。
3. **作者决定，Agent 执行。** 立项、大纲、人物、审校结论都由作者确认；Agent 只提议、起草、检查、提交。机械保证（字数、卫生、记忆、发布）放在程序里，不靠模型自觉。
4. **只给故事语言。** 界面和 Agent 对作者不出现字段名、文件名、工具名、英文枚举。信息不丢，黑话翻译。
5. **结果要新鲜。** 正文改过，旧记忆标过期；审校报告带正文版本；过期的东西不能当依据。
6. **失败要有下一步。** 每个错误都说清「发生了什么、为什么、现在可以做什么」，不静默、不假装成功。
7. **书是文件，工作台只是视图。** 作者随时能在 Finder / 编辑器里打开这本书；导出是派生品，不改正文。

## 3. 全流程

### 3.1 四阶段与七步

```
开书 ────────────── 搭骨架 ────────────── 写正文 ────────────── 完本
立项卡                全书梗概/故事线        章纲 → 写章 → 提交
人物与世界观(可后补)   第一卷 + 前3章章纲      记忆 → 审校/改写(可选)
                                              下一章 …
                                                              全书体检 → 导出
```

| 步骤 | 作者看到 | 作者做 | Agent 做 | 产物 |
| --- | --- | --- | --- | --- |
| 1. 新建作品 | 书名、题材、一句话想法、计划章数、每章字数、位置 | 填 2–4 项；位置可用默认 | 不介入（不自动调模型） | 一个独立作品文件夹 + 工作区 |
| 2. 立项 | 「先定下这本书的核心」 | 回答一次一个问题 | 按 setup 方法提问、汇总九张立项卡、一次提交 | `.narracat/data/bible/premise-cards.json` |
| 3. 搭骨架 | 「把故事搭成一个骨架」 | 确认方向、改自己不同意的地方 | 全书梗概、主故事线、第一卷卷纲与 arc、前三章章纲 | `outline-structure.json` + 章纲 JSON |
| 4. 补章纲 | 「第 N 章还差一份章纲」 | 看一遍、提要求 | 场景、冲突、人物、收束、章末钩子 | `vol-NN/ch-NNN.json` |
| 5. 写章 | 「写第 N 章」 | 点一下，等结果；不满意就改 | 取上下文包 → 写 → 卫生检查/字数 → 记本章记忆 → 发布 | 正文 + 记忆 + 提交日志 |
| 6. 审校 / 改写（可选） | 章内「审校」「改写本章」 | 决定要不要审、要改哪里 | 审只查不改；改写只动改写稿，复核后替换 | 审校报告 / 改写稿 |
| 7. 完本 | 「全书已经写完」+ 体检 | 看体检、决定是否补 | 汇总缺章、短章、记忆、审校、伏笔；导出成稿 | `exports/<书名>_<时间>.docx` 等 |

### 3.2 每一步的失败与恢复

| 失败 | 作者看到 | 恢复动作 |
| --- | --- | --- |
| 建书目录已存在 | 自动改用「书名 2」；不覆盖 | 继续，或换书名 |
| 建书成功但没加入工作区 | 明确提示作品路径 | 用 DSH 打开该目录；作品不丢 |
| 没有立项卡 | 下一步是「开始立项」，不是「写第 1 章」 | 点下一步，Agent 一次问一个问题 |
| 没有章纲就写 | 上下文包返回 `OUTLINE_MISSING`；写章提示先补章纲 | 下一步变成「补第 N 章大纲」 |
| 改写已发布章 | 上下文包不再返回正文路径，而是 `rewrite_required` + 改写稿路径 | 先开改写稿，再提交；不会撞上写保护 |
| 同一章连续提交失败 | 提交程序 3 次上限，第 4 次要求作者原话 | 问作者「再改一次还是先停」；作者同意才继续 |
| 正文手改后记忆过期 | 体检列出「N 章记忆过期」 | 逐章读正文、重记；不整本重建 |
| 审校报告过期 | 报告带 `fresh=false` | 先重审这一版，不拿旧报告当依据 |
| 导出时没有正文 | 明确说「先写第一章」 | 回下一步写章 |

### 3.3 完整体检（导出前）

体检不阻断写作或导出，只把还开着的坑说清：

- 缺章（前后章之间没有正文）
- 章比目标字数短（低于 70%）
- 记忆缺失 / 记忆过期
- 审校未过
- 伏笔未揭晓
- 全书章数是否写齐（有计划章数时才判「完成」）

这份清单由 `computeChecklist()` 计算，概览、导出对话框、Agent 的 `novel_journey` 共用。

## 4. 交互设计

### 4.1 书架：信息在左上角，目录独立滚动

- 空书架不再只让「重新扫描」，而是**「新建作品」**：从一句话开始。
- 有书时：**左上角固定显示当前书的信息**（书名、两句梗概、题材/进度/字数、继续写 + 新建作品）；**目录移到信息区下方**，是独立面板，固定高度、超出上下滚动；右侧封面海报保持固定几何，切换书不跳页。
- 「新建作品」不再藏在小顶栏里，而是和「继续写」并列放在信息区，空书架则是主 CTA。
- 有书的 CTA 按阶段变化：新书是「开始立项」，连载中是「继续写第 N 章」，完本是「完本并导出」。
- 每本书可以是一个独立工作区；也可以放在已有工作区的子目录里（此时不重复注册工作区）。

### 4.2 作品概览：一屏说清「写到哪、下一步、还差什么」

从上到下：

1. **四阶段步进条**：开书 / 搭骨架 / 写正文 / 完本，当前段点亮。
2. **书头**：封面、书名、状态、题材、梗概、进度条。
3. **下一步卡**：阶段标签 + 一句标题 + 一句说明 + 主按钮 + 次按钮（导出成稿、打开本章）。
4. **体检条**：最多两条待处理；「查看」打开完整清单。
5. **最近章节**与**本书信息**。

没有数据的区块不显示；新书不会铺一页 0。

### 4.3 新建作品对话框

- 必填只有书名；题材、一句话想法、计划章数、每章字数都有合理默认。
- 位置默认 `~/Documents/Narracat`，可点「更改」用系统目录选择器。
- 一句话想法会写进 `AGENTS.md` 的「本书想法」，Agent 每轮都能读到；不填就不建文件。
- 建完**立即关闭对话框、自动刷新书架并打开新书**，停在概览；不自动调用模型，下一步卡引导「开始立项」。
- 如果建在已有工作区里，复用该工作区，不再嵌套注册；放在默认书库则自动登记为独立工作区。

### 4.4 导出对话框

- 格式：Word（.docx）/ HTML（可打印成 PDF）/ Markdown / TXT。
- 先看体检，再导出；导出后给文件名、章节数、字数、路径和下载链接。
- 导出写在 `exports/`，不改正文；文件名带本地时间，不覆盖旧稿。
- Word 使用宋体、A4、每章另起一页；HTML 自带适合打印的排版。

### 4.5 Agent 会话

- 工作台点下一步时：立项/大纲/补章纲会**打开写作会话并发出提示**；写章在后台跑，顶栏显示进度。
- 在章节页点「写本章 / 改写本章」后，正文页直接进入**写作等待态**：正在写第 N 章、已用时、不确定进度、打开写作会话、骨架正文；需要作者回答时变成琥珀色「去会话回答」，失败时原地重试。目录里对应章节同步显示「写作中」。
- 一本书复用一个写作会话；会话的 cwd 指向这本书，**多本书的工作区也不会让工具认错书**。
- 右侧「小说」面板是分阶段看板，而不是只给已写章节的阅读器：立项看九张卡、大纲看梗概/卷/章纲、开写准备看人物与世界、写正文看下一章/前情/要留意、完本看体检与导出；未写章节点开先看章纲摘要，不再是一片空白。
- 面板会自己更新：turn 结束立即刷新，可见时按轻量文件指纹轮询，切回页面/窗口聚焦补刷；快捷提示跟着当前阶段走（继续立项 / 继续搭骨架 / 本书现状 / 本章资料 / 完本检查）。
- 主工作台按书记住上次退出的页面（分类、选中的章/人物、子视图与追踪页签），从 AI 对话切回时不再默认掉回书架。

## 5. Agent 能力设计

### 5.1 新增工具

| 工具 | 用途 |
| --- | --- |
| `novel_journey` | 返回阶段、唯一下一步、进度、体检；作者问「接下来做什么」或刚打开书时先调 |
| `novel_export_book` | 导出 docx / html / md / txt，返回路径、字数、章数与体检 |

已有 32 个工具继续负责取材料、立项、大纲、设定、写章提交、审校、记忆、实体与本体。新增 journey、export、记忆简报、追踪读写与备忘后共 38 个。

### 5.2 Prompt 约束

- 每轮只推进一件事；先 `novel_journey`，再决定动作。
- 新书先立项，一次只问一个最关键的问题，能推断的不问。
- 每完成一步，用一句人话说「存下了什么」「下一步是什么」。
- 工作区没有作品时，请作者在工作台点「新建作品」，不自己造目录。
- 作者要成稿时用 `novel_export_book`；导出前用体检清单说清还开着的坑。

### 5.3 追踪式记忆

长篇写作最大的风险不是写不出来，而是写到 200 章后忘了前情。插件把通用 Agent 工作区的「进度 / 章节摘要 / 伏笔表 / 人物状态 / 写作备忘」转成一套可见、可核对、自动刷新的记忆：

- **源**：每章记忆 `.narracat/memory/ch-NNN.json`、大纲的伏笔登记、人物身份；**派生**：`tracking/` 下四张人可读的表。
- **写前读**：`novel_memory_brief` 给进度、最近 10 章摘要、人物当前状态、未收/到期伏笔、作者备忘；上下文包再加章纲、出场人物卡、前文结尾与设定。
- **写完刷**：提交/重记/大纲/设定/作品信息保存后自动刷新四张表；作者的决定用 `novel_tracking_note` 落到写作备忘。
- **看得见**：工作台「资料 → 全书追踪」四个页签 + 写作备忘；生成表写保护，备忘可编辑。

详见 [MEMORY-TRACKING.md](MEMORY-TRACKING.md)。

### 5.4 机械保证

- 正式正文只能经 `project_chapter_submit` 发布；Agent 的文件工具与 UI 裸编辑器都写不了正文/记忆/审校/提交日志。
- 提交失败 3 次后必须问作者并带原话；**保存成功后该轮预算结束**，下一次改写重新计 3 次，不会被历史尝试卡死。
- 已发布章的上下文包明确要求先开改写稿，不返回可直接写正文的路径。
- 审校报告带正文版本；正文改过即 `fresh=false`。
- 记忆逐章记录、读时折叠；正文改过即过期。

## 7. 路线图

### P1：把「陪伴感」和「恢复力」补齐

1. **写作会话的欢迎语**：进入新书会话时，Agent 先说清「这本书现在在哪、我建议先做什么」，不必等作者开口。
2. **待处理收件箱**：把体检里的记忆过期、审校未过、缺章、名字提议收成一个「待处理」入口；每条可「交给 Agent / 忽略（记成作者决定） / 稍后」。
3. **审校一键化**：写完章后可选「顺手审一遍」，审校不通过时直接给「改这一处」的改写稿。
4. **章内改写 UI**：在章节头部显式区分「写本章 / 改写本章 / 审校」，改写稿版本可对比。
5. **多书工作区整理**：把嵌套在同一个工作区里的书一键提升为独立工作区，保证每本书都有可见的会话归属。
6. **导入旧稿**：把 Word / Markdown 旧稿分章导入为正文 + 缺记忆提示。

### P2：长篇创作的长期能力

1. **写作节奏**：每日目标、连续写作天数、断点续写；不制造打卡压力。
2. **全书一致性检查**：人物状态、时间线、伏笔回收、重复桥段；只报告，不改稿。
3. **风格与润色**：作者自己的「声音样本」+ 多版本对比；不替作者定风格。
4. **角色聊天 / 资料问答**：在设定范围内和角色对话，帮助找语气。
5. **协作与分享**：导出、只读分享、版本对比；云端同步另立项。

### 明确不做（本阶段）

- 不做 Electron 壳、SQLite 记忆库、四进程架构；DSH 已有会话、工具、沙箱与主题。
- 不做「一键全自动写完一本」：创作决定必须经过作者。
- 不做 PDF 导出（HTML 可打印成 PDF）；不做复杂排版模板。
- 不做社区、发布、版权交易。

## 8. 风险与边界

| 风险 | 现状 | 处理 |
| --- | --- | --- |
| 创建位置写到了用户没预期的目录 | 默认 `~/Documents/Narracat`，可改 | 对话框显示完整路径；建完提示路径 |
| 工作区里已有书，新建到工作区内 | 复用工作区，不重复注册 | 书架按真实目录去重；会话用书目录做 cwd |
| 嵌套书的工作区会话在侧栏不可见 | 用 `cwd` 建会话，工作台能打开 | P1 提供「提升为独立工作区」 |
| 没有计划章数时无法判「完本」 | 体检提示补计划 | 建书时默认 20 章；本书信息可改 |
| DOCX 是自写最小 OOXML | 只含标题/正文/章节分页 | 已用 python-docx 验证；复杂样式后续再加 |
| 审校默认关闭 | 合规且省成本 | 作者可开审校门；P1 做「顺手审一遍」 |
| 体检只做机械项 | 不做语义矛盾判断 | P2 接一致性检查；当前明确说「只作线索」 |
